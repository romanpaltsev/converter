# TESTING.md — тестирование

## Уровни проверок

| Уровень | Команда | Что проверяет |
|---|---|---|
| Типы | `npm run check` | TypeScript strict во всех `.ts` и `.astro` |
| Unit (Vitest) | `npm run test:unit` | определение формата по сигнатуре; имена файлов и конфликты; разбор и запись TIFF/EXIF; фильтр EXIF в обоих режимах (в режиме по умолчанию нет GPS, Orientation = 1); APP1/APP2 в JPEG (ICC больше 64 КБ — несколько сегментов); `eXIf`/`iCCP` в PNG с CRC (сверка с `node:zlib`); zlib; выбор ICC по nclx; превью; таблица маршрутов; тексты и актуальность CONTENT.md |
| Сборка (Vitest по `dist/`) | `npm run build && npm run test:dist` | title/description/H1/lang; canonical и взаимные hreflang ru/en/x-default; переключатель языка; noindex по флагу; JSON-LD; sitemap с альтернативами без 404; robots.txt; нет инлайн-скриптов, `<style>`, `style=`, `on*=`; JS только на страницах-конвертерах; разметка виджета |
| E2E (Playwright) | `npm run test:e2e` или `npm run test:e2e:docker` | Chromium, Firefox, WebKit — см. ниже |
| Медленные | `npm run test:e2e:slow` (`:docker`) | 50 × 24 Мп в Chromium без зависания интерфейса; 48 Мп → JPG и → WebP в WebKit |
| Docker | `npm run smoke:docker` (`-- --e2e`) | образ собирается, `docker compose up` отдаёт сайт; страницы, редиректы, 404 на двух языках, заголовки, `application/wasm`, gzip; с `--e2e` — все e2e против контейнера |
| Lighthouse | `npm run lighthouse` | мобильный профиль против Docker-образа |

В CI (`.github/workflows/deploy.yml`) на каждый push и pull request выполняется всё, кроме Lighthouse.

### E2E

Готовые файлы проверяются независимо от кода конвертера: EXIF и ICC — библиотекой exifr и разбором
сегментов, пиксели — декодером браузера, ZIP — fflate.

- HEIC → JPG и HEIC → PNG: размеры; ориентация по пикселям квадрантов (irot + Orientation 6, irot + imir + Orientation 5); Orientation = 1.
- PNG → JPG и JPG → PNG (`formats.spec.ts`): ICC P3 байт в байт, даты без GPS и камеры, поворот по EXIF (Orientation 6, 5, 2
  у JPEG и eXIf у PNG), прозрачность и палитра с tRNS на белом фоне, серый, 16 бит, Adam7, у APNG — первый кадр
  с предупреждением; CMYK, 12 бит, lossless и арифметический JPEG — понятные ошибки.
- WebP → JPG и WebP → PNG: ICC P3 из чанка ICCP, даты без GPS, поворот по EXIF (с префиксом «Exif\0\0» и без),
  прозрачность (lossless VP8L и lossy VP8X + ALPH) на белом фоне в JPG и прозрачная в PNG, у анимации — первый кадр.
- WebP на выходе: порядок чанков VP8X → ICCP → VP8 → EXIF и флаги VP8X (независимый разбор RIFF), ICC P3 байт в байт,
  EXIF без GPS, поворот; прозрачность (ALPH); «Без потерь» — VP8L с теми же пикселями, что у PNG; HEIC → WebP: профиль
  из nclx и предупреждение HDR; «уже в формате WebP»; изображение шире 16 383 точек — понятная ошибка.
- Любой вход на любой странице: PNG и WebP на `/heic-v-jpg` конвертируются; «уже в формате JPG» — с пояснением про iPhone
  только на HEIC-страницах; смена формата конвертирует такие строки заново.
- Режим по умолчанию: даты съёмки есть, GPS, Make/Model/SerialNumber и XMP — нет. С галочкой GPS и камера сохраняются.
- ICC: профиль исходника переносится байт в байт; nclx Display P3 → профиль Display P3; без профиля → sRGB; HDR PQ → предупреждение.
- Альфа: в JPG — белый фон, в PNG — прозрачность. Многокадровый файл → основное изображение. 10 бит → 8 бит.
- AVIF (`avif.spec.ts`): ICC и даты без GPS, irot, nclx → профиль P3, HDR PQ → предупреждение, 10 бит, прозрачность на белом
  в JPG и прозрачная в PNG, «Сохранить все метаданные» (GPS в PNG), WebP на выходе, анимация (`avis`) — основное
  изображение с предупреждением, AVIF на HEIC-странице.
- Сжатие (`compress.spec.ts`): «Исходный» сохраняет формат (HEIC → JPG, PNG с прозрачностью, WebP), файл меньше
  исходника, даты без GPS; «до размера» — файл не больше цели, в строке подобранное качество, JPEG остаётся baseline
  (SOF0); PNG — подсказка «подобрать размер нельзя»; недостижимая цель (24 Мп в 10 КБ) — качество 5 и подсказка; МБ и WebP на en.
- GIF (`gif.spec.ts`, unit `gif.test.ts`): квадранты, чересстрочный = обычный побайтно, прозрачность (на белом в JPG,
  прозрачная в PNG), анимация — первый кадр с предупреждением, кадр со смещением на большем холсте, обрезанный файл,
  LZW с KwKwK; пиксели PNG совпадают с декодированием того же GIF браузером; на «Сжать фото» GIF → PNG.
- BMP (`bmp.spec.ts`, unit `bmp.test.ts`): 24 бита, палитра 4 бита, RLE8, 16 бит 565, 1 бит, 32 бита с альфой
  (пиксели PNG совпадают с декодированием браузером), встроенный ICC V5 → в JPG байт в байт; собранные вручную —
  сверху вниз, 32 бита с нулевой альфой (непрозрачно), RLE4 со смещением (пропуски прозрачны), неподдерживаемое сжатие.
- TIFF (`tiff.spec.ts`, unit `tiff-decoder.test.ts`): LZW, Deflate с предиктором, PackBits, без сжатия (MM), JPEG,
  тайлы 128×128 с краями, 16 бит MM, серый, 1 бит CCITT G4, палитра, обычная и предумноженная альфа, многостраничный
  (первая страница с предупреждением), CMYK и RAW (DNGVersion) — ошибки; EXIF из файла без служебных тегов, GPS
  только с галочкой, ICC P3 → в JPG, Orientation 6 применяется.
- ICO (`ico.spec.ts`, unit `ico.test.ts`): размеры 16–256 (не больше исходника, из крошечной — 16), записи 32 бита,
  внутри PNG нужного размера с прозрачностью, прямоугольное — в квадрате с прозрачными полями; для ICO скрыты
  качество и метаданные, при смене формата возвращаются.
- JPEG XL (`jxl.spec.ts`, unit `jxl.test.ts`): контейнер и «голый» кодовый поток, ICC P3 и даты из бокса Exif (GPS —
  только с галочкой), Exif в brob — файл конвертируется без метаданных, ориентация из заголовка, прозрачность, анимация.
- AVIF на выходе (`avif-out.spec.ts`): бренд avif, файл декодирует браузер (поворот по EXIF применён, прозрачность
  сохранена), обратный путь через наш декодер — ICC P3 и даты без GPS на месте; вход AVIF — «уже в формате AVIF».
- Размер (`resize.spec.ts`): 24 Мп HEIC → JPG 1920×1280 по длинной стороне, готовые размеры подставляются в поле,
  маленький файл не увеличивается (предупреждение); 50 % после поворота по EXIF — квадранты на месте; ширина × высота
  с пропорциями (PNG 400×300 с прозрачностью) и без (растянуть, пустая сторона — без ограничения), WebP; неверное число
  подсвечивается (`aria-invalid`). Unit (`resize.test.ts`): размеры во всех режимах, однотонное остаётся однотонным,
  квадранты при сильном уменьшении, нет тёмной каймы у прозрачных краёв.
- Очередь: ошибки (мусор, JPEG с пояснением про iPhone) не останавливают остальные файлы, PNG и AVIF на HEIC-странице конвертируются; лимит 100 файлов; «Конвертировать заново»; «Очистить».
- ZIP: все готовые файлы, одинаковые имена с суффиксами `_2`, `_3`; у архива и у файлов, скачанных по одному, —
  дата и время в имени (проверяется формат и близость к текущему времени), внутри архива имена короткие.
- Приватность: во время конвертации и скачивания ZIP — только GET статики своего сайта, без тел запросов (плюс страж `context.route`); до выбора файла WASM и worker не загружаются, затем показывается «Загружаем конвертер…».
- CSP: заголовки на страницах и на JS/WASM; в каждом тесте автоматически ловятся нарушения CSP и ошибки консоли.
- Навигация: переключатель языка, 301 для лишних слешей, 404 на двух языках.
- Интерфейс: зона загрузки — кнопка, работает с клавиатуры и drag-and-drop; конвертер в первом экране на 360×640; axe (WCAG 2.1 AA) на всех страницах в светлой и тёмной теме, в том числе виджет с результатами.

Локально Firefox и WebKit требуют системных библиотек (`npx playwright install --with-deps` нужен sudo).
Без этого используйте `npm run test:e2e:docker` — прогон в официальном образе Playwright.

Против развёрнутого сайта — те же тесты с `E2E_BASE_URL=https://converter.hotbar.pro` (локальный сервер тогда
не запускается): `npx playwright test --project=chromium`, Firefox и WebKit — `npm run test:e2e:docker`.

## Фикстуры

Синтетические HEIC без личных данных лежат в `tests/fixtures/` (закоммичены). Их список и назначение —
в [tests/fixtures/README.md](tests/fixtures/README.md). Пересоздать: `npm run fixtures`
(Docker, Debian forky, heif-enc 1.23.6, exiftool, ImageMagick).

**Синтетически не воспроизводится** — нужна проверка на реальных фото:

- Apple MakerNote (exiftool его не создаёт; логика «переносить только Apple» покрыта unit-тестом на искусственном блоке);
- тайлы 1024×896 у 48 Мп iPhone (у фикстур тайлы 512×512);
- HDR-снимки iPhone с gain map, «Портрет» (карта глубины), Live Photo;
- серийная съёмка в формате iPhone (у фикстуры — последовательность heif-enc с основным изображением);
- HEIC с телефонов Samsung и особенности их контейнера.

## Ручной чек-лист

### iPhone, Safari

- [ ] Выбор из «Фото» (кнопка в зоне загрузки → «Медиатека»): файлы приходят как **HEIC**, а не JPEG.
      Если iOS отдала JPEG, в строке файла — пояснение «Файл уже в формате JPEG… iPhone мог сам преобразовать его».
      Проверьте и «Файлы» (Files): там HEIC передаётся как есть.
- [ ] Снимки 12, 24 и **48 Мп (HEIF Max)** конвертируются; вкладка не перезагружается (риск — память, см. CLAUDE.md).
- [ ] Пачка из 20–30 снимков: интерфейс отзывчив, прогресс «Конвертируем N из M» обновляется.
- [ ] Портретный снимок повёрнут правильно в «Фото» после сохранения.
- [ ] Цвета JPG/PNG совпадают с оригиналом при просмотре рядом (Display P3).
- [ ] Дата съёмки сохранилась (в «Фото» — свайп вверх / «i»), геолокации нет; с галочкой — геолокация есть.
- [ ] Скачивание по одному: файл сохраняется в «Файлы»/«Фото»; «Скачать всё (ZIP)» открывается в «Файлах».
- [ ] Live Photo, «Портрет», HDR, серия — конвертируются (берётся основной снимок).
- [ ] Тёмная тема, VoiceOver озвучивает зону загрузки как кнопку и прогресс.

### Android, Chrome

- [ ] HEIC с Samsung (и любые HEIC, переданные с iPhone) конвертируются.
- [ ] Пачка 20–30 файлов без подвисаний; 48 Мп — без падения вкладки.
- [ ] Скачивание по одному: больше 10 файлов подряд — Chrome не блокирует загрузки
      (если блокирует — пользоваться «Скачать всё (ZIP)»).
- [ ] ZIP открывается встроенным менеджером файлов (client-zip пишет архив версии 4.5 / ZIP64).

### Десктоп

- [ ] ZIP открывается «Проводником» Windows и Finder на macOS.
- [ ] Перетаскивание файлов из проводника в зону загрузки; файл, брошенный мимо зоны, не открывается во вкладке.

## Известные ограничения

- **Память на 48 Мп** — пик в worker около 1,3 ГБ (из них ~1 ГБ MozJPEG в сборке jSquash). На десктопе проходит;
  на iPhone нужно проверить. Если вкладка падает — своя сборка MozJPEG с построчной подачей (подробности в CLAUDE.md).
- **HDR PQ/HLG** (HEIF с камер): понижение до 8 бит без тон-маппинга, цвета могут отличаться — пользователь видит предупреждение.
- **libheif 1.22+** строже к нестандартным файлам (размер после декодирования должен совпадать с `ispe`) — проверить на Samsung.
- **headless Chromium** не запускает 11-ю подряд загрузку через `<a download>`; e2e скачивают не больше 10 файлов на тест.
